1 How to use this handout

The slides move fast and are built for discussion. This handout is the slow, complete version: read it before class if you like, and return to it when you are auditing code.

Every section follows the same pattern: a short explanation, code you can run, and Audit it boxes that show a mistake an AI assistant (or a human) could easily make.

The Audit Loop
  1. Read the code.
  2. Run it.
  3. Restate it in plain English. If you cannot say what a line does, you cannot vouch for it.
  4. Refine it or Reject it.

Setup for the examples. Every example uses movies.csv (651 movies, 32 columns). Download it here and put it in a data folder inside your Positron project. The setup code for this handout is:

library(tidyverse)
movies <- read_csv("data/movies.csv")

What changed since the older course notes. Some syntax has been modernized. The short version: use the native pipe |>, use slice_max() and slice_sample() instead of sample_n(), and use if_else() and case_when() for conditions. Appendix E has a full old-to-new table.

2 R as a calculator, and naming things

R follows normal arithmetic precedence. Use parentheses whenever you are unsure.

2 + 3 * 4
#> [1] 14
(2 + 3) * 4
#> [1] 20
2^10
#> [1] 1024
10 %/% 3 # integer division
#> [1] 3
10 %% 3 # remainder
#> [1] 1

Store a result with <-, read it aloud as “gets”. Names are case-sensitive, can contain letters, numbers, _ and ., and cannot start with a number.

runtime_min <- 95
runtime_min / 60
#> [1] 1.583333
runtime_min <- runtime_min + 5 # overwrites the old value
runtime_min
#> [1] 100
Convention

= also assigns, but R users use <- for assignment and reserve = for naming function arguments. If you see = inside a filter(), that is almost always a bug (see Section 10).

Audit it: decimals are approximate

Computers store most decimals approximately, so exact comparison can fail.

0.1 + 0.2 == 0.3
#> [1] FALSE
dplyr::near(0.1 + 0.2, 0.3)
#> [1] TRUE

When AI-written code tests two decimals for equality with ==, ask whether near() is what it meant.

3 Functions and arguments

A function has a name and arguments in parentheses. Arguments can be given by position or by name; names are safer and easier to read.

round(3.14159, 2) # by position
#> [1] 3.14
round(3.14159, digits = 2) # by name
#> [1] 3.14
round(digits = 2, x = 3.14159) # names can be in any order
#> [1] 3.14

Many arguments have defaults. ?round opens the help page; the Usage section shows every argument and its default.

round(3.14159) # digits defaults to 0
#> [1] 3

4 Vectors and types

The basic unit in R is the vector: an ordered collection of values of one type. Even a single number is a vector of length 1. Combine values with c().

scores <- c(72, 88, 91, 65)
length(scores)
#> [1] 4
scores * 2 # arithmetic works on every element
#> [1] 144 176 182 130
1:5 # a range
#> [1] 1 2 3 4 5
seq(0, 1, by = 0.25)
#> [1] 0.00 0.25 0.50 0.75 1.00
rep("Drama", 3)
#> [1] "Drama" "Drama" "Drama"

4.1 The types you will meet

Type Example class()
numeric (double) 3.5, 72 "numeric"
integer 5L "integer"
character "Drama" "character"
logical TRUE, FALSE "logical" 
class(72)
#> [1] "numeric"
class(5L)
#> [1] "integer"
class("Drama")
#> [1] "character"
class(TRUE)
#> [1] "logical"

4.2 Coercion: when types are mixed

A vector holds one type, so R converts everything to the “most flexible” type present. The order is:

logical < integer < numeric < character

c(TRUE, 2L) # logical -> integer
#> [1] 1 2
c(TRUE, 2L, 3.1) # -> numeric
#> [1] 1.0 2.0 3.1
c(TRUE, 2L, 3.1, "a") # -> character
#> [1] "TRUE" "2"    "3.1"  "a"

You can also convert on purpose with as.numeric(), as.character(), as.logical(), as.integer().

Key idea

A vector holds exactly one type, and R converts silently to make that true. After reading or converting data, always check the types.

Audit it: converting messy text to numbers

as.numeric() quietly turns anything it cannot read into NA. Real data is full of text such as "159.8 lbs".

as.numeric(c("72", "159.8 lbs", "kg"))
#> Warning: NAs introduced by coercion
#> [1] 72 NA NA

R prints a warning, but only once and easily ignored in a long script. After any conversion, count the new NAs: sum(is.na(x)). You will do this with real wearable data in the cleaning sessions.

4.3 Recycling

When vectors of different lengths are combined, the shorter one is recycled. This is fine for a single number and dangerous otherwise.

c(1, 2, 3, 4) + 10 # 10 is recycled: intended
#> [1] 11 12 13 14
c(1, 2, 3, 4) + c(10, 20) # recycled in a pattern: legal, rarely intended
#> [1] 11 22 13 24
1:3 + 1:2 # lengths don't divide evenly: R warns
#> Warning in 1:3 + 1:2: longer object length is not a multiple of shorter object length
#> [1] 2 4 4

4.4 Logical vectors: yes/no questions

Comparisons produce logical vectors. Combine them with & (and), | (or), and ! (not).

scores > 70
#> [1]  TRUE  TRUE  TRUE FALSE
scores > 70 & scores < 90
#> [1]  TRUE  TRUE FALSE FALSE
!(scores > 70)
#> [1] FALSE FALSE FALSE  TRUE

Because TRUE counts as 1 and FALSE as 0, you can count and take proportions:

sum(scores > 70) # how many
#> [1] 3
mean(scores > 70) # what fraction
#> [1] 0.75
any(scores > 90) # is at least one TRUE?
#> [1] TRUE
all(scores > 60) # are all TRUE?
#> [1] TRUE

%in% asks whether each value appears anywhere in a set. Compare it with ==:

genres <- c("Drama", "Comedy", "Horror")
genres == "Comedy"
#> [1] FALSE  TRUE FALSE
genres %in% c("Drama", "Horror")
#> [1]  TRUE FALSE  TRUE
Key idea

Comparisons make logical vectors, and logical vectors can be counted (sum), turned into proportions (mean), and used to select (x[condition]). Most of filter() is this idea applied to a column.

5 Subsetting vectors

Square brackets [ ] select elements. R counts from 1.

scores[1] # first
#> [1] 72
scores[c(1, 3)] # first and third
#> [1] 72 91
scores[-1] # everything except the first
#> [1] 88 91 65
scores[scores > 70] # keep where the condition is TRUE
#> [1] 72 88 91

which() converts a logical vector into positions:

which(scores > 70)
#> [1] 1 2 3
Audit it: out of range returns NA, not an error 
scores[10]
#> [1] NA

No error and no warning. If AI-written code indexes by position, check that the positions can exist.

6 Missing values

NA means “not available”: a value exists in the world but we do not know it. Almost any calculation involving an unknown gives an unknown.

NA + 1
#> [1] NA
NA > 5
#> [1] NA
NA == NA # is one unknown equal to another unknown? Unknown.
#> [1] NA

There are a few exceptions where the answer does not depend on the unknown:

NA & FALSE # FALSE no matter what NA is
#> [1] FALSE
NA | TRUE # TRUE no matter what NA is
#> [1] TRUE

6.1 Finding and counting NAs

NA == NA is NA, so you cannot test for missing values with ==. Use is.na().

x <- c(4, 8, NA, 2)
is.na(x)
#> [1] FALSE FALSE  TRUE FALSE
sum(is.na(x)) # how many are missing
#> [1] 1
mean(is.na(x)) # what fraction
#> [1] 0.25

6.2 Summaries with missing values

mean(x) # the unknown spreads
#> [1] NA
mean(x, na.rm = TRUE) # remove NAs first
#> [1] 4.666667
na.rm = TRUE is a decision, not a fix

Using na.rm = TRUE means “compute this on the cases where I happen to know the value”. That is only reasonable if the missing cases are not systematically different from the observed ones. In real data they often are. For example, if a smartwatch drops readings more often for certain users, ignoring missing readings quietly changes whose data you are analyzing. Always ask: who is missing, and why?

Audit it: NA inside a logical subset 
x[x > 5]
#> [1]  8 NA

The result contains an NA row for the unknown. Applying the same idea to a data frame with filter() behaves differently (it drops those rows), which is also a quiet change. See Section 10.

7 Lists and data frames

A list is like a vector but each element can be a different type or length.

car <- list(make = "Ford", year = 1999, used = TRUE)
car$make # by name
#> [1] "Ford"
car[["year"]] # double brackets pull out the element itself
#> [1] 1999
car["year"] # single brackets return a smaller list
#> $year
#> [1] 1999

A data frame is a list of equal-length vectors, one per column. In the tidyverse we use tibbles, which are data frames that print more helpfully.

df <- tibble(
  title = c("A", "B", "C"),
  runtime = c(95, 120, NA),
  rated_r = c(TRUE, FALSE, TRUE)
)
df
#> # A tibble: 3 × 3
#>   title runtime rated_r
#>   <chr>   <dbl> <lgl>  
#> 1 A          95 TRUE   
#> 2 B         120 FALSE  
#> 3 C          NA TRUE

Every column is a vector, so everything from Sections 4 to 6 applies to columns.

df$runtime # pull one column out as a vector
#> [1]  95 120  NA
mean(df$runtime, na.rm = TRUE)
#> [1] 107.5

dim(movies) # rows, columns

summary() gives quick numeric summaries, including how many NAs each column has:

summary(movies$runtime)
#>    Min. 1st Qu.  Median    Mean 3rd Qu.    Max.     NAs 
#>    39.0    92.0   103.0   105.8   115.8   267.0       1
Key idea

A data frame is a list of equal-length vectors, so each column is a vector and every vector rule above applies to it.

8 Importing data

readr::read_csv() reads a comma-separated file. It guesses each column’s type from the first rows and tells you what it chose.

movies <- read_csv("data/movies.csv")

Useful arguments:

Argument What it does Example
na = which text means missing na = c("", "NA", "-999")
skip = skip metadata lines at the top skip = 2
comment = ignore lines starting with a character comment = "#"
col_types = set types yourself cols(zip = col_character())
n_max = read only the first rows n_max = 1000

Related readers: read_tsv() (tabs), read_delim() (any delimiter), readxl::read_excel() (Excel files), and arrow::read_parquet() (Parquet, which we use for large data in Session 2).

Where is my file? Paths like "data/movies.csv" are relative to your working directory. Check it with getwd(). In Positron, opening a folder as your workspace sets the working directory to that folder.

Audit it: the guessed type can destroy information

ZIP codes look like numbers, and R will happily treat them as numbers, dropping the leading zero.

read_csv(I("zip,n\n01234,5"))
#> # A tibble: 1 × 2
#>   zip       n
#>   <chr> <dbl>
#> 1 01234     5
read_csv(I("zip,n\n01234,5"), col_types = cols(zip = col_character()))
#> # A tibble: 1 × 2
#>   zip       n
#>   <chr> <dbl>
#> 1 01234     5

Always check the column types after reading a file, and set col_types for identifiers, codes, and anything with leading zeros.

9 The pipe

The pipe |> takes what is on its left and passes it as the first argument of the function on its right. Read it as “then”.

# nested: read from the inside out
head(arrange(filter(movies, genre == "Drama"), imdb_rating), 3)

# piped: read top to bottom
movies |>
  filter(genre == "Drama") |>
  arrange(imdb_rating) |>
  head(3)

Style: one verb per line, pipe at the end of the line, indent two spaces. Short lines are easier to restate.

Debugging a pipeline: run it one step at a time. Highlight everything up to a pipe (not including it) and run it to see the intermediate result.

Other pipes you will see. %>% is the older tidyverse pipe and behaves the same for almost everything in this course. AI tools and older tutorials use both. They differ in how you place the data when it is not the first argument:

movies |> lm(imdb_rating ~ critics_score, data = _) # native pipe: placeholder is _
movies %>% lm(imdb_rating ~ critics_score, data = .) # magrittr pipe: placeholder is .
Key idea

Read |> as “then”. When a pipeline misbehaves, run it one step at a time and look at each intermediate result.

10 Data manipulation with dplyr

dplyr verbs follow four rules:

  1. The first argument is a data frame.
  2. The other arguments say what to do with it.
  3. The result is a data frame.
  4. Nothing is modified in place.

The four core verbs, at a glance:

Verb Works on What it does
select() columns choose, drop, or reorder columns
filter() rows keep rows where a condition is TRUE
arrange() rows change the order of rows
mutate() columns create or change columns
Audit it: a pipeline that is never saved 
movies |> filter(genre == "Drama") |> nrow()
#> [1] 305
nrow(movies) # movies itself is unchanged
#> [1] 651

If you want to keep a result, assign it: dramas <- movies |> filter(genre == "Drama"). Conversely, AI code that starts movies <- movies |> filter(...) permanently overwrites your data. Check which one you are reading.

10.2 filter(): keep rows

filter() keeps rows where the condition is TRUE. Several conditions separated by commas mean and.

movies |>
  filter(genre == "Drama", imdb_rating > 8) |>
  select(title, imdb_rating)
#> # A tibble: 8 × 2
#>   title                  imdb_rating
#>   <chr>                        <dbl>
#> 1 Warrior                        8.2
#> 2 V for Vendetta                 8.2
#> 3 The Help                       8.1
#> 4 Good Will Hunting              8.3
#> 5 The Prestige                   8.5
#> 6 No Country for Old Men         8.1
#> # ℹ 2 more rows

More tools: | (or), %in% (membership), between() (inclusive range), and is.na().

movies |> filter(genre %in% c("Drama", "Comedy")) |> nrow()
#> [1] 392
movies |> filter(between(imdb_rating, 7, 8)) |> nrow()
#> [1] 226
movies |> filter(is.na(runtime)) |> select(title, runtime)
#> # A tibble: 1 × 2
#>   title              runtime
#>   <chr>                <dbl>
#> 1 The End of America      NA
Audit it: == against a vector

== compares position by position and recycles the shorter vector. It does not mean “equal to either”.

movies |> filter(genre == c("Drama", "Comedy")) |> nrow() # wrong
#> [1] 191
movies |> filter(genre %in% c("Drama", "Comedy")) |> nrow() # right
#> [1] 392

R prints a warning about lengths in your console. Warnings are clues.

Audit it: comparing with NA

Anything compared with NA is NA, and filter() drops rows where the condition is not TRUE.

movies |> filter(dvd_rel_year != NA) |> nrow() # wrong: zero rows
#> [1] 0
movies |> filter(!is.na(dvd_rel_year)) |> nrow() # right
#> [1] 643
Audit it: filter() silently drops NA rows 
nrow(movies)
#> [1] 651
movies |> filter(runtime > 0) |> nrow() # every runtime is positive, but one row vanished
#> [1] 650
movies |> filter(runtime > 0 | is.na(runtime)) |> nrow() # keep unknowns on purpose
#> [1] 651

Any time a row count changes unexpectedly, ask where the rows went. Row-count checks before and after each step are a core habit.

Audit it: and/or precedence

& is evaluated before |, like multiplication before addition. Use parentheses.

movies |>
  filter(genre == "Drama" | genre == "Comedy" & imdb_rating > 8) |>
  nrow()
#> [1] 306
movies |>
  filter((genre == "Drama" | genre == "Comedy") & imdb_rating > 8) |>
  nrow()
#> [1] 9
Audit it: typos and case give zero rows, not errors

Text comparison is exact and case-sensitive.

movies |> filter(genre == "drama") |> nrow()
#> [1] 0
movies |> filter(genre == "Drama") |> nrow()
#> [1] 305

A result with zero rows is a clue that a category name is wrong. Check the real values first with distinct(genre).

Audit it: = instead of == 
movies |> filter(genre = "Drama")
#> Error in `filter()`:
#> ! We detected a named input.
#> ℹ This usually means that you've used `=` instead of `==`.
#> ℹ Did you mean `genre == "Drama"`?

This one is friendly: dplyr stops and explains. Not every mistake is.

10.3 arrange(): sort rows

Sorting is ascending by default. Use desc() for descending, and add more columns to break ties.

movies |>
  arrange(desc(imdb_rating), title) |>
  select(title, imdb_rating)
#> # A tibble: 651 × 2
#>   title                  imdb_rating
#>   <chr>                        <dbl>
#> 1 The Godfather, Part II         9  
#> 2 Django Unchained               8.5
#> 3 Memento                        8.5
#> 4 Promises                       8.5
#> 5 The Prestige                   8.5
#> 6 Aliens                         8.4
#> # ℹ 645 more rows
Audit it: the most common AI mistake

“Show the 5 highest-rated movies” written as arrange(imdb_rating) |> head(5) returns the five lowest. No error, no warning, a believable table.

movies |> arrange(imdb_rating) |> select(title, imdb_rating) |> head(5)
#> # A tibble: 5 × 2
#>   title             imdb_rating
#>   <chr>                   <dbl>
#> 1 Disaster Movie            1.9
#> 2 Epic Movie                2.3
#> 3 Battlefield Earth         2.4
#> 4 Viva Knievel!             2.7
#> 5 Doogal                    2.8

For top-N questions, slice_max() states the intent directly:

movies |>
  slice_max(imdb_rating, n = 5, with_ties = FALSE) |>
  select(title, imdb_rating)
#> # A tibble: 5 × 2
#>   title                  imdb_rating
#>   <chr>                        <dbl>
#> 1 The Godfather, Part II         9  
#> 2 Promises                       8.5
#> 3 Django Unchained               8.5
#> 4 Memento                        8.5
#> 5 The Prestige                   8.5

with_ties = FALSE returns exactly 5 rows. The default keeps all tied rows, which can return more than you asked for.

10.4 mutate(): create or change columns

mutate() adds new columns (at the end) or overwrites existing ones.

movies |>
       mutate(runtime_hrs = runtime / 60, decade = thtr_rel_year %/% 10 * 10) |>
       select(title, runtime_hrs, decade)
#> # A tibble: 651 × 3
#>   title                runtime_hrs decade
#>   <chr>                      <dbl>  <dbl>
#> 1 Filly Brown                 1.33   2010
#> 2 The Dish                    1.68   2000
#> 3 Waiting for Guffman         1.4    1990
#> 4 The Age of Innocence        2.32   1990
#> 5 Malevolence                 1.5    2000
#> 6 Old Partner                 1.3    2000
#> # ℹ 645 more rows

Use if_else() for two outcomes and case_when() for several. They check that the outcomes are the same type, which catches mistakes that base ifelse() hides.

movies |>
  mutate(
    length_class = case_when(
      runtime < 90 ~ "short",
      runtime <= 120 ~ "medium",
      runtime > 120 ~ "long"
    )
  ) |>
  count(length_class)
#> # A tibble: 4 × 2
#>   length_class     n
#>   <chr>        <int>
#> 1 long           120
#> 2 medium         428
#> 3 short          102
#> 4 <NA>             1

Rows that match no condition (here, the movie with an NA runtime) become NA. You can set a default with .default = "unknown".

mutate() keeps all other columns. To keep only the new ones, use mutate(..., .keep = "none"). This replaces the older transmute().

Preview: count()

count(x) counts rows for each value of x. It is shorthand for grouping and summarizing, which is the first topic in Session 2.

For random samples use slice_sample() (this replaces sample_n() and sample_frac()). Set a seed so the sample is reproducible:

set.seed(531)
movies |> slice_sample(n = 3) |> select(title)
#> # A tibble: 3 × 1
#>   title          
#>   <chr>          
#> 1 Mad Dog Time   
#> 2 Blue Valentine 
#> 3 The Big Red One
Audit it: ambiguous questions get confident answers

“How many documentaries are there?” The data has two columns that could mean that:

movies |> filter(genre == "Documentary") |> nrow()
#> [1] 52
movies |> filter(title_type == "Documentary") |> nrow()
#> [1] 55

Neither answer is a bug. The question was underspecified. A good prompt names the column, and a good audit confirms which one was used.

11 Reading control flow, loops, and functions

AI-written code often wraps pipelines in functions, loops, and if statements. You will rarely write these from scratch in this course, but you must be able to read them.

11.1 if and else

if tests one TRUE/FALSE. It is not vectorized.

x <- 7
if (x < 0) {
  "negative"
} else if (x > 0) {
  "positive"
} else {
  "zero"
}
#> [1] "positive"

To choose values for a whole column, use the vectorized if_else() or case_when() inside mutate() instead.

Audit it: if with a vector 
if (c(TRUE, FALSE)) {
  "yes"
}
#> Error in `if (c(TRUE, FALSE)) ...`:
#> ! the condition has length > 1

R refuses a condition with length greater than one. If you see if applied to a column, expect an error or a misunderstanding.

11.2 for loops

A for loop repeats code once per element.

for (g in c("Drama", "Comedy")) {
  n <- sum(movies$genre == g)
  cat(g, ":", n, "movies\n")
}
#> Drama : 305 movies
#> Comedy : 87 movies

How to read it: “for each genre g in this list, count the movies and print.” Loops are fine, but when AI uses a loop to build up a data frame row by row, ask whether one verb (count(), summarize()) would do the same thing more clearly.

11.3 Functions

A function packages code under a name, with arguments as inputs and the last expression as the returned value.

to_hours <- function(minutes, digits = 1) {
  round(minutes / 60, digits)
}

to_hours(95)
#> [1] 1.6
to_hours(95, digits = 2)
#> [1] 1.58
movies |>
  mutate(runtime_hrs = to_hours(runtime)) |>
  select(title, runtime, runtime_hrs)
#> # A tibble: 651 × 3
#>   title                runtime runtime_hrs
#>   <chr>                  <dbl>       <dbl>
#> 1 Filly Brown               80         1.3
#> 2 The Dish                 101         1.7
#> 3 Waiting for Guffman       84         1.4
#> 4 The Age of Innocence     139         2.3
#> 5 Malevolence               90         1.5
#> 6 Old Partner               78         1.3
#> # ℹ 645 more rows

How to read an AI-written function: find the arguments and their defaults, find what is returned (the last line or an explicit return()), and look for anything it uses that was not passed in. Functions can silently read variables from outside (Appendix B).

movies |> filter(mpaa_rating == c("R", "PG-13"))

Appendix

These sections cover material from the older notes that you will meet in AI-written code but will not use often.

A. Matrices and arrays

A matrix is a vector with a dim attribute. It is filled one column at a time.

m <- matrix(1:6, nrow = 2, ncol = 3)
m
#>      [,1] [,2] [,3]
#> [1,]    1    3    5
#> [2,]    2    4    6
m[1, 3] # row 1, column 3
#> [1] 5
m[, 2] # all of column 2
#> [1] 3 4
m[-1, ] # drop row 1
#> [1] 2 4 6

Data frames are not matrices, but df[row, col] indexing works similarly.

B. Scope and lazy evaluation

Scope. If a function cannot find a variable inside itself, R looks in the surrounding environment. This is convenient and risky: a function can quietly depend on a variable that is not one of its arguments.

cutoff <- 100
is_long <- function(minutes) minutes > cutoff # cutoff is NOT an argument
is_long(120)
#> [1] TRUE
cutoff <- 150
is_long(120) # same call, different answer
#> [1] FALSE

Lazy evaluation. Function arguments are only evaluated when they are used.

f <- function(x) {
  cat("Hello\n")
  x
}
f(stop("this error only fires when x is used"))
#> Hello
#> Error in `f()`:
#> ! this error only fires when x is used

“Hello” prints first: the broken argument is not touched until the function needs it. You will meet the same idea at a larger scale with the arrow package in Session 2, where a query on a huge Parquet file is not run until you ask for the result.

C. Vectorization

Most R functions work on whole vectors at once, which is faster and shorter than a loop. But vectorized code can hide edge cases.

p <- c(0.5, 0.5, 0, 0)
-sum(p * log(p)) # entropy: wrong, 0 * log(0) is NaN
#> [1] NaN
p_pos <- p[p > 0]
-sum(p_pos * log(p_pos)) # right: drop the zero-probability cells
#> [1] 0.6931472

NaN means “not a number”. It is a cousin of NA that spreads the same way, and is.na() detects both.

If a function was written for single values and you need it for vectors, Vectorize() can wrap it, but if_else() and case_when() are usually better inside mutate().

D. The apply family and purrr

apply() and lapply() apply a function across rows, columns, or list elements. The tidyverse version is purrr::map(), with variants that return a specific type (map_dbl() for numbers, map_chr() for text).

nums <- movies |> select(imdb_rating, critics_score, audience_score, runtime)

lapply(nums, mean, na.rm = TRUE) |> unlist() # base R
#>    imdb_rating  critics_score audience_score        runtime 
#>       6.493088      57.688172      62.362519     105.821538
map_dbl(nums, mean, na.rm = TRUE) # purrr: guaranteed numeric result
#>    imdb_rating  critics_score audience_score        runtime 
#>       6.493088      57.688172      62.362519     105.821538

Prefer map_*() over sapply(): sapply() guesses the output type, and a surprise type is a classic silent failure.

E. Old syntax to new syntax

Older code you may see Use now Why
x %>% f() x \|> f() built into R, no package needed
sample_n(df, 5) / sample_frac(df, .1) slice_sample(df, n = 5) / slice_sample(df, prop = .1) one consistent slice_* family
