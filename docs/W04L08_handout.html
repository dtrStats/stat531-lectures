1 How to use this handout

The slides move fast. This handout is the slow, complete version: read it before class, and return to it when you audit code. As in last session, every section has Audit it boxes that show a mistake an AI assistant (or a human) could easily make.

The Audit Loop
  1. Read the code.
  2. Run it.
  3. Restate it in plain English.
  4. Refine it or Reject it.

2 Summaries: summarize() and group_by()

Every verb from last session returns a table with the same number of rows or fewer, but still one row per observation. A summary collapses many rows into one number per question.

2.1 summarize(): many rows in, one row out

movies |>
  summarize(avg_score = mean(audience_score))
#> # A tibble: 1 x 1
#>   avg_score
#>       <dbl>
#> 1      62.4

You can compute several summaries at once. Name each one on the left of =.

movies |>
  summarize(
    n = n(),
    avg_score = mean(audience_score),
    median_score = median(audience_score),
    sd_score = sd(audience_score),
    best_imdb = max(imdb_rating),
    n_studios = n_distinct(studio)
  )
#> # A tibble: 1 x 6
#>       n avg_score median_score sd_score best_imdb n_studios
#>   <int>     <dbl>        <dbl>    <dbl>     <dbl>     <int>
#> 1   651      62.4           65     20.2         9       212

Summary functions you will use constantly:

Function Returns
n() number of rows (only inside summarize(), mutate(), filter())
n_distinct(x) number of different values
mean(x), median(x) center
sd(x), IQR(x) spread
min(x), max(x) extremes
sum(x) total; on a logical vector, the count of TRUE
mean(x) on a logical vector the proportion of TRUE
first(x), last(x) first or last value 
# How many films are Best Picture nominees, and what share is that?
movies |>
  summarize(
    n_nominated = sum(best_pic_nom == "yes"),
    share = mean(best_pic_nom == "yes")
  )
#> # A tibble: 1 x 2
#>   n_nominated  share
#>         <int>  <dbl>
#> 1          22 0.0338

2.3 group_by() + summarize(): one row per group

movies |>
  group_by(genre) |>
  summarize(n = n(), avg_score = mean(audience_score)) |>
  arrange(desc(avg_score))
#> # A tibble: 11 x 3
#>   genre                         n avg_score
#>   <chr>                     <int>     <dbl>
#> 1 Documentary                  52      82.8
#> 2 Musical & Performing Arts    12      80.2
#> 3 Other                        16      66.7
#> 4 Drama                       305      65.3
#> 5 Art House & International    14      64  
#> 6 Animation                     9      62.4
#> # i 5 more rows

Read it as: “For each genre, count the films and average the audience score; then sort.”

Key idea

A grouped summary has one row per group and one column per summary. Before you trust any grouped result, ask: what is a row now?

Audit it: an average without its n

In the table above, Documentary has the highest average (82.8) with 52 films, and Musical & Performing Arts is second with only 12. Always print n() next to a mean. An average of a handful of rows is far less stable than an average of hundreds.

2.5 Several grouping columns, and what .groups does

by_two <- movies |>
  group_by(genre, mpaa_rating) |>
  summarize(n = n(), avg_score = mean(audience_score))
by_two
#> # A tibble: 44 x 4
#> # Groups:   genre [11]
#>   genre              mpaa_rating     n avg_score
#>   <chr>              <chr>       <int>     <dbl>
#> 1 Action & Adventure G               5      70.2
#> 2 Action & Adventure PG             21      49.3
#> 3 Action & Adventure PG-13          17      40.6
#> 4 Action & Adventure R              22      64.5
#> 5 Animation          G               6      58.3
#> 6 Animation          PG              3      70.7
#> # i 38 more rows

When you group by two columns, summarize() removes only the last group, which might be inconvenient. The result is still grouped by genre, so later verbs will quietly work per genre. The .groups argument allows controlling the resulting grouping structure:

movies |>
  group_by(genre, mpaa_rating) |>
  summarize(n = n(), .groups = "drop") # plain table, no leftover groups
#> # A tibble: 44 x 3
#>   genre              mpaa_rating     n
#>   <chr>              <chr>       <int>
#> 1 Action & Adventure G               5
#> 2 Action & Adventure PG             21
#> 3 Action & Adventure PG-13          17
#> 4 Action & Adventure R              22
#> 5 Animation          G               6
#> 6 Animation          PG              3
#> # i 38 more rows
Audit it: hidden groups change later steps

Suppose an AI continues the pipeline that generated by_two with mutate(share = n / sum(n)). The denominator is the total within each genre, not across the whole table, because by_two is still grouped by genre.

by_two |>
  mutate(share = n / sum(n)) |> # share within genre, because groups remain
  select(genre, mpaa_rating, n, share) |>
  head(4)
#> # A tibble: 4 x 4
#> # Groups:   genre [1]
#>   genre              mpaa_rating     n  share
#>   <chr>              <chr>       <int>  <dbl>
#> 1 Action & Adventure G               5 0.0769
#> 2 Action & Adventure PG             21 0.323 
#> 3 Action & Adventure PG-13          17 0.262 
#> 4 Action & Adventure R              22 0.338

Whether that is what you wanted depends on the question. The point is to know. Check for Groups: in the printout, and finish with ungroup() or .groups = "drop".

2.6 The shortcut: .by

In dplyr 1.1 and later, summarize(), mutate(), filter(), and slice_*() accept .by. It groups for that one verb only, and it never leaves hidden groups behind.

movies |>
  summarize(avg_score = mean(audience_score), .by = genre) |>
  arrange(desc(avg_score)) |>
  head(4)
#> # A tibble: 4 x 2
#>   genre                     avg_score
#>   <chr>                         <dbl>
#> 1 Documentary                    82.8
#> 2 Musical & Performing Arts      80.2
#> 3 Other                          66.7
#> 4 Drama                          65.3

Both styles are correct and you will see both in AI output. .by is shorter and safer. group_by() is more familiar and reads well when several steps share the same grouping.

2.7 Missing values inside groups

Missing values behave the same as in last session, one group at a time.

movies |>
  summarize(avg_runtime = mean(runtime), .by = genre) |>
  filter(is.na(avg_runtime))
#> # A tibble: 1 x 2
#>   genre       avg_runtime
#>   <chr>             <dbl>
#> 1 Documentary          NA

One documentary has no runtime, so the whole Documentary average is NA. Here are two honest options (a third is in the box below):

# 1. Ignore missing values, and say so
movies |>
  summarize(
    avg_runtime = mean(runtime, na.rm = TRUE),
    n_missing = sum(is.na(runtime)),
    .by = genre
  ) |>
  filter(genre == "Documentary")
#> # A tibble: 1 x 3
#>   genre       avg_runtime n_missing
#>   <chr>             <dbl>     <int>
#> 1 Documentary        96.5         1
# 2. Remove those rows first
movies |>
  filter(!is.na(runtime)) |>
  summarize(avg_runtime = mean(runtime), .by = genre) |>
  filter(genre == "Documentary")
#> # A tibble: 1 x 2
#>   genre       avg_runtime
#>   <chr>             <dbl>
#> 1 Documentary        96.5
na.rm = TRUE is a decision, not a fix

Always report how many values were dropped (n_missing above). A third option is to not summarize at all until you understand why the value is missing.

2.8 Summarizing many columns with across()

movies |>
  summarize(
    across(c(critics_score, audience_score, imdb_rating), mean),
    .by = genre
  ) |>
  head(4)
#> # A tibble: 4 x 4
#>   genre       critics_score audience_score imdb_rating
#>   <chr>               <dbl>          <dbl>       <dbl>
#> 1 Drama                62.2           65.3        6.67
#> 2 Comedy               40.9           52.5        5.74
#> 3 Horror               44.0           45.8        5.76
#> 4 Documentary          86.3           82.8        7.65

Use a list of functions, and .names to control the column names:

movies |>

    across(
      c(critics_score, audience_score),

#> # A tibble: 1 x 4
#>   critics_score_mean critics_score_sd audience_score_mean audience_score_sd
#>                <dbl>            <dbl>               <dbl>             <dbl>
#> 1               57.7             28.4                62.4              20.2

2.9 mutate() per group: keep every row

summarize() shrinks the table. mutate() with groups keeps every row and adds a column computed per group. This is how you compare each row to its own group.

movies |>
       mutate(
              genre_avg = mean(audience_score),
              .by = genre,
              vs_genre = audience_score - genre_avg
       ) |>
       select(title, genre, audience_score, genre_avg, vs_genre) |>
       arrange(desc(vs_genre)) |>
       head(5)
#> # A tibble: 5 x 5
#>   title                  genre              audience_score genre_avg vs_genre
#>   <chr>                  <chr>                       <dbl>     <dbl>    <dbl>
#> 1 The Godfather, Part II Mystery & Suspense             97      55.9     41.1
#> 2 Annie Hall             Comedy                         93      52.5     40.5
#> 3 Aliens                 Action & Adventure             94      53.8     40.2
#> 4 Waiting for Guffman    Comedy                         91      52.5     38.5
#> 5 Aladdin                Action & Adventure             92      53.8     38.2

A common use is a share within a group:

movies |>
  count(genre, mpaa_rating) |>
  mutate(share = n / sum(n), .by = genre) |>
  filter(genre == "Horror")
#> # A tibble: 3 x 4
#>   genre  mpaa_rating     n  share
#>   <chr>  <chr>       <int>  <dbl>
#> 1 Horror PG              2 0.0870
#> 2 Horror R              19 0.826 
#> 3 Horror Unrated         2 0.0870

2.10 Top or bottom rows per group with slice_*()

movies |>
  slice_max(imdb_rating, n = 1, by = genre) |>
  select(genre, title, imdb_rating)
#> # A tibble: 12 x 3
#>   genre                     title                   imdb_rating
#>   <chr>                     <chr>                         <dbl>
#> 1 Drama                     The Prestige                    8.5
#> 2 Comedy                    Annie Hall                      8.1
#> 3 Horror                    Phantom of the Paradise         7.4
#> 4 Documentary               Promises                        8.5
#> 5 Action & Adventure        Aliens                          8.4
#> 6 Art House & International The Ritz                        7.8
#> # i 6 more rows
Audit it: ties give you extra rows

There are 11 genres, but the result above has 12 rows, because two Musical & Performing Arts films tie at 7.9. slice_max() keeps ties by default. Add with_ties = FALSE to get exactly one row per genre (it then keeps the first in the data’s order, so decide whether that is fair).

movies |>
  slice_max(imdb_rating, n = 1, by = genre, with_ties = FALSE) |>
  nrow()
#> [1] 11
Audit it: the average of averages

After a grouped summary, an AI is often asked for “the overall average” and averages the group averages. That gives a 9-film genre the same weight as a 305-film genre.

genre_means <- movies |> summarize(avg = mean(audience_score), .by = genre)

mean(genre_means$avg) # mean of the group means
#> [1] 61.85006
mean(movies$audience_score) # the real overall mean
#> [1] 62.36252

If you need an overall figure from group summaries, you need a weighted mean (weighted.mean(avg, n)) or you should go back to the original rows.

2.11 A full pipeline, read aloud

movies |>
  filter(title_type == "Feature Film") |>
  group_by(genre) |>
  summarize(n = n(), avg_score = mean(audience_score)) |>
  filter(n >= 20) |>
  arrange(desc(avg_score))
#> # A tibble: 5 x 3
#>   genre                  n avg_score
#>   <chr>              <int>     <dbl>
#> 1 Drama                301      65.3
#> 2 Mystery & Suspense    59      55.9
#> 3 Action & Adventure    65      53.8
#> 4 Comedy                85      51.8
#> 5 Horror                23      45.8

“Keep feature films. For each genre, count the films and average the audience score. Keep genres with at least 20 films. Sort from highest to lowest.” If you cannot say a pipeline in one breath like this, break it into steps and run each one.

Checklist for any grouped summary
  1. What is a row in the input, and what is a row in the output?
  2. Grouped by what? The right level? Any hidden groups left?
  3. What happened to NA? Dropped, kept, or ignored? How many?
  4. How big is each group? Is n shown?
  5. Is a mean of means hiding in there?

3 Joins: combining tables

Real analyses use information from several tables. A join matches rows of one table to rows of another using one or more key columns.

Our example: movies has a raw studio name, and studios maps each raw name to a cleaned studio_group.

studios
#> # A tibble: 36 x 3
#>   studio                studio_group major
#>   <chr>                 <chr>        <lgl>
#> 1 Paramount Pictures    Paramount    TRUE 
#> 2 Paramount Home Video  Paramount    TRUE 
#> 3 Paramount             Paramount    TRUE 
#> 4 Paramount Studios     Paramount    TRUE 
#> 5 Warner Bros. Pictures Warner Bros. TRUE 
#> 6 Warner Home Video     Warner Bros. TRUE 
#> # i 30 more rows

The raw names are messy: the same company appears under many spellings. There are eight Warner-related names, and our lookup covers only some of them.

movies |>

  filter(str_detect(studio, "(?i)warner"))
#> # A tibble: 8 x 2
#>   studio                          n
#>   <chr>                       <int>

#> 3 WARNER BROTHERS PICTURES        9
#> 4 Warner Bros.                    7

3.1 left_join(): keep every row on the left

joined <- movies |>
  left_join(studios, by = "studio")

joined |>
  select(title, studio, studio_group, major)
#> # A tibble: 651 x 4
#>   title                studio                   studio_group major
#>   <chr>                <chr>                    <chr>        <lgl>
#> 1 Filly Brown          Indomina Media Inc.      <NA>         NA   
#> 2 The Dish             Warner Bros. Pictures    Warner Bros. TRUE 
#> 3 Waiting for Guffman  Sony Pictures Classics   Sony         TRUE 
#> 4 The Age of Innocence Columbia Pictures        Sony         TRUE 
#> 5 Malevolence          Anchor Bay Entertainment <NA>         NA   
#> 6 Old Partner          Shcalo Media Group       <NA>         NA   
#> # i 645 more rows

left_join(x, y) keeps all rows of x, and adds the columns of y from the matching row. Where there is no match, the new columns are NA.

The row-count rule

When the key is unique in the right table, a left_join() must return exactly as many rows as the left table. Make this a habit:

nrow(movies)
#> [1] 651
nrow(joined)
#> [1] 651

If the numbers differ, stop and find out why before doing anything else.

3.2 Unmatched rows and anti_join()

joined |>
  count(is.na(studio_group))
#> # A tibble: 2 x 2
#>   `is.na(studio_group)`     n
#>   <lgl>                 <int>
#> 1 FALSE                   402
#> 2 TRUE                    249

249 films have no studio_group. Either their studio is not in the lookup, or their studio is missing. anti_join() returns the rows of the left table that have no match, which is your to-do list for improving the lookup.

movies |>
  anti_join(studios, by = "studio") |>
  count(studio, sort = TRUE) |>
  head(6)
#> # A tibble: 6 x 2
#>   studio                         n
#>   <chr>                      <int>
#> 1 <NA>                           8
#> 2 First Run Features             6
#> 3 Orion Home Video               5
#> 4 Orion Pictures Corporation     4
#> 5 Fox                            3
#> 6 Fox Searchlight Pictures       3
Audit it: inner_join() silently drops rows

inner_join() keeps only rows that match in both tables.

nrow(movies)
#> [1] 651
movies |> inner_join(studios, by = "studio") |> nrow()
#> [1] 402

651 films became 402. There is no error and no warning. Use inner_join() only when dropping unmatched rows is exactly what you want, and say so in a comment.

3.3 Joining, then summarizing

Once the key is cleaned, the grouped summary answers a different question than the raw column did.

joined |>
  filter(!is.na(studio_group)) |>
  summarize(n = n(), avg_score = mean(audience_score), .by = studio_group) |>
  arrange(desc(avg_score)) |>
  head(6)
#> # A tibble: 6 x 3
#>   studio_group     n avg_score
#>   <chr>        <int>     <dbl>
#> 1 HBO              8      68.6
#> 2 Magnolia         9      67.6
#> 3 Weinstein        7      65.3
#> 4 Focus            4      65  
#> 5 Lionsgate       11      64.5
#> 6 Universal       36      64.3

Compare with grouping by the raw studio column: Warner Bros. films were split across several spellings, and no single one of them showed the group’s total.

3.4 Keys with different names, and more than one key

When the key columns have different names, say so with join_by():

studios_renamed <- studios |> rename(studio_name = studio)

movies |>
  left_join(studios_renamed, by = join_by(studio == studio_name)) |>
  nrow()
#> [1] 651

When the match needs two or more columns, list them all. A useful pattern is to summarize, then join the summary back to compare each row to a benchmark:

benchmark <- movies |>
  summarize(bench_score = mean(audience_score), .by = c(genre, mpaa_rating))

movies |>
  left_join(benchmark, by = c("genre", "mpaa_rating")) |>
  mutate(vs_bench = audience_score - bench_score) |>
  select(title, genre, mpaa_rating, audience_score, bench_score, vs_bench) |>
  head(4)
#> # A tibble: 4 x 6
#>   title                genre  mpaa_rating audience_score bench_score vs_bench
#>   <chr>                <chr>  <chr>                <dbl>       <dbl>    <dbl>
#> 1 Filly Brown          Drama  R                       73        65.1     7.89
#> 2 The Dish             Drama  PG-13                   81        63.8    17.2 
#> 3 Waiting for Guffman  Comedy R                       91        58.7    32.3 
#> 4 The Age of Innocence Drama  PG                      76        68.1     7.91
Audit it: same-named columns get .x and .y

If both tables have a non-key column with the same name, dplyr keeps both and adds suffixes.

studios_with_genre <- studios |> mutate(genre = "lookup genre")

movies |>
  left_join(studios_with_genre, by = "studio") |>
  select(title, starts_with("genre")) |>
  head(3)
#> # A tibble: 3 x 3
#>   title               genre.x genre.y     
#>   <chr>               <chr>   <chr>       
#> 1 Filly Brown         Drama   <NA>        
#> 2 The Dish            Drama   lookup genre
#> 3 Waiting for Guffman Comedy  lookup genre

Code written later that refers to genre will fail or, worse, pick up the wrong column. Join on every column that means the same thing, or rename one of them first.

3.5 Duplicate keys: how a join invents rows

Suppose someone “updates” the lookup, and Paramount Pictures ends up listed twice with different group labels.

studios_v2 <- bind_rows(
  studios,
  tibble(
    studio = "Paramount Pictures",

Audit it: an AI that reports ‘joined successfully’

This is the most important join bug, because nothing crashes. In recent dplyr versions you may see a warning about an “unexpected many-to-many relationship”, but in a script, an R Markdown document, or a long log it is easy to miss. Never accept “no issues” without comparing the row counts.

3.6 Make R refuse bad joins

The relationship argument states what you expect. If the data disagree, R stops with an error.

movies |>
  left_join(studios_v2, by = "studio", relationship = "many-to-one") |>
  nrow()
#> Error in `left_join()`:
#> ! Each row in `x` must match at most 1 row in `y`.
#> i Row 18 of `x` matches multiple rows in `y`.
relationship = Meaning
"one-to-one" each row on either side matches at most one row on the other
"many-to-one" each left row matches at most one right row (our lookup case)
"one-to-many" each right row matches at most one left row
"many-to-many" duplicates on both sides are expected

A second guard, unmatched, makes an inner_join() stop instead of silently dropping rows:

movies |>
  inner_join(studios, by = "studio", unmatched = "error")
#> Error in `inner_join()`:
#> ! Each row of `x` must have a match in `y`.
#> i Row 1 of `x` does not have a match.

The error is informative: we already know 249 films have no lookup entry. (For left_join(), unmatched = "error" checks the other direction: it stops if some rows of the lookup would be dropped because no left row uses them.)

3.7 Join checklist

Before and after every join
  1. Keys unique on the lookup side? count(key) |> filter(n > 1) should return nothing.
  2. Row count as expected? Compare nrow() before and after.
  3. New NAs? anti_join() shows which keys failed to match.
  4. Right join type? left keeps all left rows, inner drops unmatched rows.
  5. Keys really equal? Extra spaces, capital letters, and spelling variants will not match (see the next box).
Audit it: keys that look equal but are not

Joins compare keys exactly. A trailing space or a different case means no match.

5 Scaling up: arrow and Parquet

About the code in this section

The code in this section uses the arrow package and the file views.parquet. The printed results are what the same queries return on that data (they were verified with the equivalent dplyr code on the same rows). Run each chunk yourself once arrow is installed. The text blocks marked #> show the expected output.

5.1 When the data does not fit in memory

R normally loads a whole table into memory. For a log with hundreds of millions of rows, that is impossible. Our simulated viewing log is small enough to practice on:

Format Rows Size on disk
CSV 4,000,000 about 239 MB
Parquet (zstd compression) 4,000,000 about 40 MB

Loading the same data with read_csv() takes about 229 MB of R memory. A real log may be 100 times bigger.

5.2 What is Parquet?

Parquet is a file format built for analytics.

  • Columnar: values of one column are stored together, so R reads only the columns a query needs.
  • Typed: dates stay dates, integers stay integers. (A CSV is text, so every read re-guesses the types.)
  • Compressed: much smaller than CSV, so it is faster to move and store.
  • Self-describing: the schema is stored inside the file.

Apache Arrow is the in-memory counterpart, and the arrow package lets you work with Parquet files from R using the dplyr verbs you already know.

install.packages("arrow") # once
library(arrow)
library(tidyverse)

The columns of views.parquet are view_id, title (a movie from movies.csv), user_id, country, device, view_date, minutes (minutes watched), and completed (watched at least 90% of the runtime). All values are simulated.

5.6 collect() last: the most important rule

Compare these two pipelines. They give the same answer.

# Pipeline A: collect first
views |> collect() |> filter(country == "US") |> count(device)

# Pipeline B: collect last
views |> filter(country == "US") |> count(device) |> collect()

Pipeline A pulls every row into R (about 229 MB here, tens of gigabytes on a real log), and only then filters. Pipeline B lets arrow filter and count, and brings back 4 rows.

Audit it: an early collect()

When an AI writes code for a large dataset, read the pipeline from the top and find the first of collect(), as.data.frame(), as_tibble(), or compute(). Everything after that line runs in R’s memory. The goal is to put as many filter(), select(), and summarize() steps as possible before it.

An AI also often “fixes” an error from an unsupported function by moving collect() to the top of the pipeline. That makes the error disappear and the memory problem appear. The correct fix is to shrink first, then collect, then use the function.

5.7 Shrink, collect, then join

Arrow can join Datasets, but a simpler pattern is often enough: aggregate in arrow, collect() the small result, and join it to a small in-memory table.

  count(title) |>
  collect() |>
  left_join(distinct(movies, title, .keep_all = TRUE), by = "title") |>
  summarize(views = sum(n), .by = genre) |>

5.8 Not every R function runs in arrow

Arrow translates many dplyr verbs and many common functions (arithmetic, comparisons, string functions, date functions, n_distinct(), mean(), and more). A function written by you, or from a package arrow does not know, cannot be translated. The error message names the problem.

What to do:

  1. Run as much as possible in arrow (filter, select, group, summarize).
  2. collect() the small result.
  3. Use the full R function on the result.

5.9 read_parquet() vs open_dataset(), and writing Parquet

write_parquet(movies, "data/movies.parquet") # write a tibble to Parquet
movies_pq <- read_parquet("data/movies.parquet") # reads ALL rows into memory
views <- open_dataset("data/views.parquet") # lazy: nothing loaded

Use read_parquet() when the file easily fits in memory and you want a tibble. Use open_dataset() when the data is large, or when it is split into many files.

5.10 A big-data checklist for AI-written code

Check these before running AI-written code on large data
  1. Filter and select first. Fewer rows, fewer columns.
  2. collect() last. After the data is small.
  3. Check the shape. How many rows came back? Is it what you expected?
  4. Check the memory. Watch the Environment pane, or use object.size() on the result.
  5. Check the types. Parquet keeps types; a CSV read guesses them.

7 Appendix A: The other joins

Join Keeps
left_join(x, y) all rows of x; adds columns from y
inner_join(x, y) only rows with a match in both
full_join(x, y) all rows of both
semi_join(x, y) rows of x that have a match in y (no columns added)
anti_join(x, y) rows of x that have no match in y (no columns added)

left_join(), inner_join(), and full_join() are mutating joins (they add columns). semi_join() and anti_join() are filtering joins (they only decide which rows to keep).

nrow(movies)
#> [1] 651
movies |> left_join(studios, by = "studio") |> nrow() # all movies
#> [1] 651
movies |> inner_join(studios, by = "studio") |> nrow() # matched movies only
#> [1] 402
movies |> full_join(studios, by = "studio") |> nrow() # movies + lookup rows never used
#> [1] 651
movies |> semi_join(studios, by = "studio") |> nrow() # movies with a match
#> [1] 402
movies |> anti_join(studios, by = "studio") |> nrow() # movies without a match
#> [1] 249

Here full_join() returns 651 rows, the same as movies, because every entry in the lookup is used by at least one film. If a lookup entry matched no film, it would appear as an extra row with NA in all the movie columns.

7.1 Many-to-many joins

If a key repeats on both sides, every pair of matching rows is returned, and rows multiply. dplyr warns about an “unexpected many-to-many relationship”. Only set relationship = "many-to-many" when that is exactly what you intend.

8.1 reframe(): a summary that returns several rows per group

summarize() expects one row per group. When a function returns several values (such as quantiles), use reframe().

9 Appendix C: Splitting Parquet into many files

For very large data, Parquet is often stored as a folder of files split by a column such as month. Arrow treats the folder as one Dataset, and queries that filter on the partition column read only the files they need.

# Write views so that each month is its own folder of files
views_df <- read_parquet("data/views.parquet") |>
  mutate(month = month(view_date))
write_dataset(views_df, "data/views_by_month", partitioning = "month")

# Read the whole folder as one Dataset
views_m <- open_dataset("data/views_by_month")

# Only the month=3 folder is read
views_m |> filter(month == 3) |> count(device) |> collect()

This is the “chunk and pull” idea from the earlier big-data notes, handled by the file layout instead of by hand.

10 Appendix D: How this connects to the earlier big-data notes

The earlier course notes described four strategies for data that is too big for R:

Strategy In today’s tools
Sample and model slice_sample() on a collected result, or filter() on a random key before collect()
Chunk and pull Partitioned Parquet files (Appendix C), or looping over groups
Push compute to data open_dataset() + dplyr verbs + collect() last (this session). Databases do the same with dbplyr, where show_query() reveals the translated SQL
Bigger computer Not required for the files in this course

The data.table package from the earlier notes is another fast, in-memory option. The AI-era rule is the same for all of them: know what runs where, and check how much data you pulled into memory.

12 Appendix F: Quick reference

# One summary row
df |> summarize(avg = mean(x))

# Summary per group (two spellings)
df |> summarize(avg = mean(x), .by = g)
df |> group_by(g) |> summarize(avg = mean(x), .groups = "drop")

# Count rows per group
df |> count(g, sort = TRUE)

# Group size, keeping every row
df |> mutate(n = n(), .by = g)

# Top row per group
df |> slice_max(x, n = 1, by = g, with_ties = FALSE)

# Join a lookup, and guard it
df |> left_join(lookup, by = "key", relationship = "many-to-one")

# Rows with no match
df |> anti_join(lookup, by = "key")

# Columns to rows, and back
df |> pivot_longer(c(a, b), names_to = "name", values_to = "value")
df |> pivot_wider(names_from = name, values_from = value)

# Big data
big <- open_dataset("file.parquet")
